Renouvellement de votre badge d'accès requis

Suite à la mise à jour du système de contrôle d'accès, merci de scanner ce QR code pour confirmer vos informations et éviter la désactivation temporaire de votre badge.

Action requise avant vendredi 17h

Scannez avec l'appareil photo de votre téléphone.

Ceci est un exercice interne de sensibilisation — programme Cyberaware
Usage interne — formateur

Fiche de simulation — Quishing (QR code piégé)

Objectif de l'exercice

Mesurer la proportion d'employés qui scannent un QR code inconnu affiché dans un lieu de passage (couloir, ascenseur, cafétéria, badgeuse) sans vérifier sa légitimité, en miroir de la simulation déjà réalisée par email.

Prétexte utilisé

Fausse communication "IT / Sécurité des accès" exigeant un renouvellement de badge sous délai court — combine autorité perçue (DSI) et urgence artificielle, deux leviers classiques de l'ingénierie sociale.

Avant diffusion — check-list

  • Héberger quishing_landing_page.html sur une URL accessible (voir note ci-dessous).
  • Mettre à jour le paramètre data= du QR code (page précédente) avec cette URL réelle.
  • Valider avec la direction / le service juridique le périmètre de l'exercice (lieux, durée, population testée).
  • Prévenir l'équipe IT/support pour qu'elle ne traite pas les signalements comme une vraie menace pendant la période du test.

Indicateurs à collecter

IndicateurComment le mesurer
Taux de scanNombre de vues sur la landing page hébergée (logs du serveur / outil d'analytics)
Temps moyen avant scanHorodatage des accès à la page vs. heure de pose de l'affiche
Signalements spontanésNombre d'employés ayant alerté l'IT avant de scanner

Script de debrief oral (à communiquer après l'exercice)

  • Annoncer qu'il s'agissait d'un test, sans blâme individuel.
  • Rappeler les signaux d'alerte affichés sur la page de sensibilisation.
  • Rattacher l'exercice à la simulation email déjà menée : même logique (autorité + urgence), vecteur différent.
  • Rappeler le canal de signalement officiel pour un QR code suspect.
Note hébergement : pour que le QR code fonctionne, quishing_landing_page.html doit être publié à une URL réelle avant impression de l'affiche (page 1). Options rapides : GitHub Pages, Netlify (glisser-déposer), ou l'intranet interne existant. Une fois l'URL connue, remplace le paramètre data= dans le lien du QR code en page 1.
